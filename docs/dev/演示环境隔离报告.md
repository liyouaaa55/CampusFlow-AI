## 2. 连接、建表与"迁移"

### 2.1 连接统一入口（`database/sqlite_db.py:84-117`）

```python
@contextmanager
def get_connection(db_path: str | Path | None = None) -> Iterator[sqlite3.Connection]:
    connection = sqlite3.connect(str(path), timeout=CONNECTION_TIMEOUT)  # 10s busy_timeout
    connection.row_factory = sqlite3.Row
    connection.execute("PRAGMA foreign_keys = ON")
    if WAL_MODE_ENABLED:
        connection.execute("PRAGMA journal_mode = WAL")
    # ... 幂等建表 SCHEMA_STATEMENTS ...
```

- **超时**：`CONNECTION_TIMEOUT = 10.0`（等效 `PRAGMA busy_timeout`）。
- **外键**：`PRAGMA foreign_keys = ON`（每条新连接都设；非持久化）。
- **WAL**：由 `WAL_MODE_ENABLED` 控制（仓库中默认开启）。
- **建表**：在 `get_connection` 内执行 `SCHEMA_STATEMENTS`（幂等：`CREATE TABLE IF NOT EXISTS / CREATE INDEX IF NOT EXISTS`）。**任意一次连接**都会保证表与索引齐全，无需独立"迁移"步骤。
- 业务表清单（来自 `SCHEMA_STATEMENTS` 与 `docs/dev/demo_db.py:60-68` 一致）：
  - `tasks`、`task_logs`、`task_feedback`、`task_submissions`
  - `verifications`、`task_closures`、`task_metadata`

### 2.2 显式 `init_db`（`database/sqlite_db.py:121-125`）

```python
def init_db(db_path=None) -> Path:
    with get_connection(db_path):
        pass
    return resolve_db_path(db_path)
```

- **幂等建表，不删任何数据**。即便演示库已含 13 条任务，再调一次 `init_db` 也不会清空。
- `demo_app.py` 启动时调一次（确保空库就位）；`demo_seed.py:414` 在 `prepare()` 之前也调一次。
- 这是当前**唯一**的"建表"入口；**没有** `migrate / upgrade / downgrade` 类工具。

### 2.3 没有独立迁移文件

`docs/dev/` 与 `database/` 下均无 `migrations/`、`alembic/`、`schema.sql`、`schema.diff`。表结构变更以"在 `SCHEMA_STATEMENTS` 改写 + 幂等"方式承担；旧库升级只能靠兼容字段或人工 SQL。

## 6. WAL、连接、外键

只读 PRAGMA 核对（`data/demo/demo.db` 当前连接）：

| Pragma | 值 | 来源 |
|---|---|---|
| `journal_mode` | `wal` | `PRAGMA journal_mode = WAL`（`sqlite_db.py:101`，受 `WAL_MODE_ENABLED` 控制） |
| `foreign_keys` | 由每条连接 `PRAGMA foreign_keys = ON` 设定 | `sqlite_db.py:99` |
| `busy_timeout` | 10 s | `CONNECTION_TIMEOUT = 10.0` + `sqlite3.connect(timeout=...)` |
| `synchronous` / `cache_size` 等 | 未显式设置 | 沿用 SQLite 默认 |

副作用：

- WAL 模式下库会**伴随 `-wal` 与 `-shm` 副文件**；复制 / 删除 / 移动时**三者必须同处理**。
- 直接 `shutil.copy(demo.db, ...)` 会得到"少数据"快照；演示库备份统一用 `sqlite3.Connection.backup()`（`docs/dev/demo_db.py:225-251` `safe_backup`）以保证合并 WAL。
- `data/demo/demo.db-wal` 当前 0 字节（`shm` 32 KiB），说明无未 checkpoint 数据；如录制中数据库被打开且有写入，请先停实例再备份。

## 8. 当前"不可重置"的根因分析

| 工具 | 设计意图 | 现实 | 后果 |
|---|---|---|---|
| `demo_db.py reset` | 把 demo.db 恢复到基线 | `data/demo/baseline/` 为空 | **明确失败**（基线缺失即中止） |
| `demo_seed.py` | 一键播种 | 检测到已有任务即中止 | **无法重新播种** |
| `demo_db.py init` | 创建空库 | 仅幂等建表，不删数据 | **不是清空** |
| `demo_db.py backup` | 保存基线 | 任何时候都可执行 | **尚未调用**（按之前边界） |

→ **当前 demo.db（13 条 + 5 附件 + 2 闭环）是一次性资源**。在没有 baseline 的情况下，"清空后重新播种"没有"一键"子命令，只能**手动**走以下流程，且每一步都是写库动作。
