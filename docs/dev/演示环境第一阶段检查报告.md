## 3. 开发库与未来演示库能否可靠隔离？

**结论：能，且已经有完整的代码依据。**

| 隔离层面 | 代码依据 | 评价 |
|---|---|---|
| 配置层（路径常量） | `config/settings.py` 模块级 `DB_PATH/UPLOAD_DIR/DATA_DIR`；import 时复制到 `sqlite_db.DB_PATH` 与 `submission_view.SUBMISSION_DIR` | 静态、明确；**无环境变量覆盖**意味着行为可预测，但**修改路径只能改源码** |
| 切换层 | `docs/dev/demo_app.py` 启动时调 `activate_demo_paths()` 改 5 个全局；顺序写在入口里 | 设计正确，**与 `from app import main` 紧耦合**；任何未来"在中间插入 import"的改动都可能破坏 |
| 路径守卫 | `docs/dev/demo_db.py:assert_demo_path` + `PROTECTED_PATHS` | CLI 写入路径的硬性屏障；保证 `demo_db.py` 与 `demo_seed.py` 不会误伤开发库 |
| 函数层 | 所有 store 函数的 `db_path` 默认参数 + `resolve_db_path` 兜底 | 提供**显式覆盖**能力；测试与未来"按库切换"全部走这条通道 |
| 测试隔离 | `tmp_path` + `monkeypatch.setattr(sqlite_db, "DB_PATH", tmp_path/...)` + AppTest 渲染 | 已在 `tests/test_demo_db_isolation.py` 等 40 个测试中验证；`tests/test_v22_ui_browser.py` 还替换了真实 LLM |
| 启动入口 | `run.bat` / `deploy.sh` → `app.py`（开发库）；`docs/dev/demo_app.py` → 演示库 | 入口分离；**未来部署到腾讯云时必须显式选择入口** |

**剩余风险**：

1. **没有"环境变量覆盖 DB 路径"机制**。如果未来需要在同一台机器上同时跑开发库与演示库，**目前无法用环境变量区分**；只能靠不同入口（不同 `streamlit run` 命令）。建议第二阶段引入 `CAMPUSFLOW_DB_PATH` 环境变量。
2. **`activate_demo_paths()` 改 5 个全局对象**，是副作用式 patch。pytest 之外没有自动验证 import 顺序是否仍正确；如果未来有人在 `app.py` 顶部新增 `from xxx import yyy`（恰好依赖 `settings`），可能在 import 阶段就触发"先加载再切换"的 bug。
3. **当前 8501 实例（PID 31932）使用全局 Python310 而非 venv 内的 Python**（命令行可见）→ 部署到腾讯云时若按 8501 习惯启动，可能误用系统 Python。

## 7. 风险、尚未验证事项、第二阶段需负责人确认内容

### 7.1 当前机制存在的风险

| 风险 | 严重度 | 说明 |
|---|---|---|
| 开发库 0 闭环、演示库闭环来自 seed | 高 | **未在真实浏览器走通完整闭环**；演示库闭环是 `demo_seed.py` 直接写入，第四页闭环展示在 UI 上未人工验证 |
| 8501 仍在用全局 Python310 跑开发库 | 中 | 录制时若沿用 `run.bat` 习惯会误用系统 Python |
| 没有环境变量覆盖 DB 路径 | 中 | 同机同时跑开发库/演示库只能靠不同入口；未来扩展性受限 |
| `data/uploads` 40+ 测试材料未清理 | 中 | 上传控件可能误选历史文件 |
| `data/submissions` 存在重名附件 | 中 | `referenced_attachment_names` 只按文件名匹配，重名时可能误判 |
| **30 个 modified + 18 个 untracked 关键文件全部未提交** | **高** | 当前工作区是**唯一可信来源**；按 HEAD 打包会得到功能残缺镜像 |

| 演示库未基线化 | 高 | `demo_db.py reset` 必失败；`demo_seed.py` 必中止；重复录制无复位 |
| `docs/dev/_test.db-wal/-shm` 未被 `.gitignore` 覆盖 | 低 | `.gitignore` 写的是 `docs/dev/_*.db`，未含 `-wal`/`-shm` |
