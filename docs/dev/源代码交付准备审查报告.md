### 4.3 若发现历史密钥泄露的处理建议（**当前未发现，仅预案**）

- **不擅自改写历史**。`git filter-repo` / `git rebase -i` / `git commit --amend` 都会改写 HEAD 之前的提交，破坏其他协作者的克隆。
- **如确认泄露**：
  1. 立即**在云端作废**该 Key（DeepSeek 后台 revoke）。
  2. **重新生成**新 Key。
  3. 走 `git filter-repo --invert-paths --path .env`（或对应文件），并强制推送（**仅限已与所有协作者沟通后**）。
  4. 通知所有 fork / clone 该仓库的协作者。
  5. 监控 `git log -p` 在 GitHub 上的搜索结果；GitHub 会在收到主动通知后协助清理 cached views。
